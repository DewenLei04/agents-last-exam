HF Sandboxes

Run the supported Ubuntu subset as one fresh Hugging Face Job per run unit. The orchestrator runs on your machine or CI runner, while the task sandbox runs on HF. This is useful when you don't have local Docker, a cloud account, or GPU hardware of your own.

Supported Linux subset
Uses the same image and CPU task list as the local Docker provider. Tasks asking for more resources than the selected HF flavor fail before a Job is created. With the shipped cpu-upgrade flavor, 3 of the 99 listed tasks fail this check.

What runs where

The hfsandbox provider starts one HF Job per run unit from agentslastexam/ale-ubuntu22-docker, then talks to it over the job's exposed port. The orchestrator needs this repository, its Python dependencies, an HF management token, and outbound HTTPS. It can run on a laptop, a CI runner, or another HF Job.

Host requirements

  • A host HF token that can manage Jobs and access the gated dataset and private bucket (hf auth login, or HF_TOKEN in the environment).
  • A positive HF Jobs credit balance for paid runs.
  • A separate HF_INFERENCE_TOKEN with only permission to call HF Inference Providers for the agent.
  • Approved access to the gated task-data dataset on Hugging Face.
  • A private HF bucket containing input, software, and encrypted reference archives.
  • A separate private ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD on the orchestrator host.
hf auth whoami
uv sync --all-packages

Fetch task data once

The image ships without task inputs or references. Request access to the ALE task-data archive, prepare a private bucket with layout <domain>/<task>/<variant>/{input,software,reference.7z,reference.required} for variants with a reference, or {input,software,reference.absent} for variants without one, then mount it read-only. Encrypt each task's reference directory into reference.7z before upload. Do not upload any plaintext reference/ directory: agents can browse the entire mount.

Use a new, randomly generated password stored only in the orchestrator's ignored secret/.env (or its process environment) as ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD. The repository's secret/.env.example contains a public ALE_REFERENCE_ARCHIVE_PASSWORD for other task-data paths. Do not reuse that value for this bucket. The preparation script reads ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD from its process environment; ALE later loads the same value from secret/.env when running the experiment. A wrong password fails evaluation. 

export ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD='your-new-private-password'
hf download agents-last-exam/agents-last-exam-data-archive \
  ale-tasks-data.tar.gz --repo-type dataset --local-dir ./ale-download
mkdir -p ./task-data
tar xzf ./ale-download/ale-tasks-data.tar.gz -C ./task-data
uv run python scripts/prepare_hf_task_data.py ./task-data ./hf-ready-data
hf buckets create <your-namespace>/<new-private-bucket> --private
hf buckets sync ./hf-ready-data hf://buckets/<your-namespace>/<new-private-bucket> --dry-run
hf buckets sync ./hf-ready-data hf://buckets/<your-namespace>/<new-private-bucket>

Run the preparation command on a trusted host with 7z installed. The destination must be new; the script rejects unexpected files and symlinks. It writes reference.required alongside each reference archive and reference.absent for variants without one. A missing archive or marker then fails before the agent runs. Put the same private password in secret/.env as ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD=... before running the experiment. Upload into a new private bucket so older plaintext reference files cannot remain alongside the encrypted archives. Keep the password set on the orchestrator host for evaluation; never set it as an HF Job secret or commit it to this repository.

Use agents with executor: sandbox. The orchestrator rejects local and docker executors for encrypted mounted data because they can access host files or the host process environment.

Use the shipped environment

Point volumes at your own bucket in configs/environments/hfsandbox.yaml before running: 

volumes:
  - hf://buckets/<your-namespace>/<your-bucket>:/mnt/ale-task-data:ro
task_data_source: mounted:/mnt/ale-task-data

The premade example_hfsandbox_exp.yaml combines this environment with configs/agents/openhands_cli_hf.yaml (GLM-5.3 through the HF router) and selected_tasks/docker_support.txt.

The orchestrator uses the token from hf auth login (or its own HF_TOKEN) to manage Jobs and read task data. Create a separate fine-grained token with only the "Make calls to Inference Providers" permission. Put it in the ignored secret/.env as HF_INFERENCE_TOKEN=hf_..., or export that variable before running the example. Create secret/.env if it does not exist, and add the private archive password there too. Keep using the management token for hf auth login. The agent receives only the inference token; keep ALE_MOUNTED_REFERENCE_ARCHIVE_PASSWORD on the orchestrator host and never forward it to a sandbox Job. 

uv run python -m ale_run run example_hfsandbox_exp.yaml --dry-run
uv run python -m ale_run run example_hfsandbox_exp.yaml

--dry-run only lists the task matrix. It does not check token permissions, bucket contents, or whether each task fits the selected hardware, and it does not start a paid Job.

For data-less tasks only (demo, tool_smoke) you can drop volumes and use task_data_source: baked_in_sandbox instead.

Resource sizing

The provider uses a startup wrapper because the currently published ALE image binds cua-server to loopback. The wrapper changes the entrypoint at Job startup to bind 0.0.0.0. It also accepts a rebuilt image whose entrypoint already has that setting.

Set flavor to cpu-basic, cpu-upgrade, cpu-xl, or cpu-performance (default cpu-upgrade, 8 vCPU / 32 GB). Some tasks in docker_support.txt require 16 vCPU / 60 GB. With the shipped cpu-upgrade flavor, those 3 tasks fail before Job creation. Set flavor: cpu-xl to run the full 99-task list, or remove those 3 tasks from a copy of the list to keep the cheaper default. Check current Jobs pricing before choosing a larger flavor; the exposed port is billed separately. A cold pull of the ~40 GB image can take 10-15 minutes; start_timeout accounts for that. idle_timeout applies only to transport: sandbox; job_timeout is the hard per-job cap for the default transport.

For a short connection check with another image, set image_ref and a list-valued job_command. The command must start a CUA server on the selected image's declared port and bind to 0.0.0.0; otherwise the exposed Job port cannot reach it. Omit job_command to run the image's usual entrypoint. A connection check does not validate task software or scoring. 

uv run python scripts/smoke_hf_provider.py

This bounded check uses a pinned AMD64 CUA image, verifies the provider's CUA command path, and cancels its Job. It does not use task data or an agent.

Output options

The default output_path: local copies produced files through the exposed port. See Choose where task output goes for other destinations.

Current limits

  • Linux tasks only, same subset as the local Docker provider.
  • The Job runs in a container that shares the host kernel; it is not VM-isolated.
  • Reference archives prevent direct plaintext access during the agent phase, but grading still runs in the same container. An agent that leaves a background process may observe evaluation-time decryption. Use a separate trusted evaluator for strict anti-leak guarantees.
  • transport: sandbox (the HF Sandbox API port-proxy) is available but not the default — prefer transport: job.
